# 微信小程序质量检查表

> 平台限制按当前官方文档与目标基础库核对。未执行真机检查的项不能算通过。

## 工程识别

- [ ] 已识别微信原生 / uni-app / Taro，而不是把 Web 项目当小程序。
- [ ] 已读取项目配置和依赖版本。
- [ ] 页面均已注册，路径和分享路径一致。
- [ ] 未擅自迁移技术栈或重写业务。

## 导航

- [ ] 无特殊需求时使用原生导航。
- [ ] TabBar 2–5 项，优先 3–4 项，每项有文字。
- [ ] TabBar 图标为本地资源，符合尺寸/大小建议。
- [ ] custom tabBar 有完整状态同步与安全区。
- [ ] 自定义导航读取状态栏和胶囊位置，不硬编码。
- [ ] 自定义导航不复刻微信胶囊，不对抗系统手势。
- [ ] 路由使用 navigateTo/redirectTo/switchTab/navigateBack 的正确语义。
- [ ] 连续点击不会打开多个相同页面。

## 安全区域与布局

- [ ] 固定底栏加 `env(safe-area-inset-bottom)` 或等价能力。
- [ ] 页面内容有与底栏等高的占位。
- [ ] 全面屏、非全面屏均实际检查。
- [ ] 弹窗、Action Sheet 和聊天输入处理底部安全区。
- [ ] 状态栏/胶囊区域没有交互冲突。
- [ ] 大屏/PC 小程序限制内容宽度，不无限拉伸。

## 键盘与输入

- [ ] iOS 和 Android 真机分别输入中文。
- [ ] input 的 adjust-position/键盘高度处理与目标版本匹配。
- [ ] 备注、聊天和多字段表单不被键盘遮挡。
- [ ] 提交按钮在键盘弹起时仍可用。
- [ ] 键盘收起后页面没有错误滚动。

## 组件与渲染

- [ ] 原生组件（map/video/canvas/camera 等）层级经过实测。
- [ ] 弹窗/筛选不会被原生组件覆盖或裁剪。
- [ ] 不假设 Skyline 与 WebView 的 CSS/组件行为完全一致。
- [ ] 自定义组件样式隔离和外部类使用正确。
- [ ] 图片 mode 和尺寸明确，失败有占位。
- [ ] 长文本、长标题和系统字号不破坏布局。

## 性能

- [ ] 首屏只加载必要资源。
- [ ] 图片尺寸合理，长列表懒加载/分页。
- [ ] 避免频繁 setData 大对象或整页数据。
- [ ] 持续动画和模糊/重阴影在低端机验证。
- [ ] 评估分包与按需注入。
- [ ] 主包与分包分享路径可访问。

## 分享、授权与隐私

- [ ] 分享入口真实，分享内容无敏感信息。
- [ ] 登录、手机号、头像昵称、位置、相册按需授权。
- [ ] 拒绝授权有替代路径。
- [ ] 隐私政策、同意与撤回入口符合当前规则。
- [ ] 端上不保存 AppSecret 等敏感密钥。

## 验证环境

- [ ] 静态代码审查完成，问题分级记录。
- [ ] 微信开发者工具编译通过并走核心路径。
- [ ] 至少一台 iOS 与一台 Android 真机验证。
- [ ] 弱网/断网验证。
- [ ] 真机验证键盘、安全区、分享、授权、性能。
- [ ] 未执行项明确列出，不声称全部通过。

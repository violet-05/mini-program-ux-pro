# 兼容性与环境边界

## 支持的技术栈

| 技术栈 | 检测方式 | 设计数据 | 静态审查 |
| --- | --- | --- | --- |
| 微信原生 | `app.json`、`project.config.json` | `data/stacks/wechat-native.csv` | 页面/WXML/WXSS/JSON |
| uni-app | `@dcloudio/*`、`pages.json` | `data/stacks/uni-app.csv` | Vue/pages.json/条件编译线索 |
| Taro | `@tarojs/*`、`app.config.*`、`package.json` | `data/stacks/taro.csv` | app.config/TSX/JSX/Vue |
| 浏览器原型 | 只有 HTML，无小程序配置 | 通用设计规则 | 仅标记为浏览器原型 |

当项目同时有多个标记时，依赖优先于生成文件。实际版本仍由项目 `package.json` / 配置决定。

## 三种验证环境

### A. 静态代码审查

已实现：

```bash
python scripts/audit_mini_program.py --path . --format markdown
```

能读取：

- 配置和页面列表；
- WXML/Vue/TSX 模板；
- WXSS/SCSS/CSS；
- 代码中的平台 API 线索；
- 设计系统 token（若存在）。

不能证明：

- 页面实际渲染；
- 键盘/安全区；
- 分享/授权；
- 性能；
- 读屏；
- 业务数据正确。

### B. 浏览器预览

本项目**没有内置浏览器运行/截图自动化**。如果用户自己运行 H5 或 HTML 原型，可以人工查看，但必须标注为“浏览器预览”。

浏览器结果不能等同于微信小程序；uni-app/Taro 的 H5 和微信目标行为不同。

### C. 微信开发者工具模拟器

本版提供**可选**的模拟器自动化适配器：

- `scripts/devtools_adapter.py` 检测 CLI / 服务端口并调用 Node 验收脚本；
- `verification/devtools/verify.cjs` 使用 `miniprogram-automator` 启动/连接开发者工具、截图和点击；
- 需要用户手动开启开发者工具“设置 → 安全设置”的服务端口；
- 运行前在 `verification/devtools` 执行 `npm install`；
- 核心 Skill 仍无 Node 依赖。

实际验证（2026-10-27）：

- 微信开发者工具 2.02.2608070；
- 基础库 3.17.4；
- 模拟器 390×844；
- 24/24 检查通过；
- 9 张截图；
- 0 个 `console.error`，0 个未捕获异常。

当前采用官方 `cli auto` + `automator.connect`。`miniprogram-automator@0.13.0` 的旧 `launch()` 与当前 DevTools 返回时序不兼容，不能假设旧教程可直接运行。

### D. 真机

本版**不提供真机自动化**。iOS/Android 真机需要在真实设备执行并记录：

- 设备/系统/微信版本/基础库/渲染引擎；
- 键盘与安全区；
- 分享/授权；
- 音频中断/性能；
- 页面/状态；
- 结果与截图。

只有实际执行才能标记通过。模拟器截图不能替代真机。

## 平台差异

### 导航

- 原生导航：系统处理返回/胶囊；
- 自定义导航：必须运行时计算状态栏和胶囊；
- uni-app/Taro：可编译到多端，H5 导航/分享/安全区不等于微信。

### 样式

- WXSS 支持 rpx，但不是完整浏览器 CSS；
- Skyline/WebView 支持范围可能不同；
- CSS 自定义属性支持取决于目标基础库；
- `env(safe-area-inset-bottom)` 需真机验证并提供回退；
- uni-app/Taro 的 px→rpx、scoped、深度选择器受编译配置影响。

### 原生组件

map/video/canvas/camera 等层级和覆盖能力需实测。不要假设 CSS z-index 在所有引擎都有效。

### 键盘

input/键盘遮挡在不同客户端和输入法下不同，必须真机验证。

### 分享/授权/隐私

受平台版本、场景和隐私规则影响；不能仅靠静态代码确认合规。

### 运行时 API

数据与规则标注“需按目标基础库验证”的，不得当作已经验证。项目版本不同可能不适用。

## 不支持的技术栈

当前没有：

- 支付宝/抖音等其他小程序专属规则；
- Flutter/React Native；
- 桌面 Web 设计系统；
- 小程序框架自动迁移。

请不要把 Web/React Native 规则直接改名为小程序规则。

## 项目安全边界

- 静态审查只读，不执行项目脚本；
- 生成器只写显式 `--output`；
- 安装器只写目标 skills 目录；
- 不要求 API Key；
- 不默认联网。

## 已知限制

1. 中文检索不是语义模型，长自然语言可能需要重写。
2. 产品/风格数据是人工整理的设计参考，不是市场研究结论。
3. 平台规则会变化，核验日期见数据。
4. 静态审查是启发式，存在漏报/误报。
5. 生成器不验证实现结果。
6. 未接入视觉模型，不能声称自动审美理解。
7. 开发者工具自动化仅覆盖模拟器，不等于真机；未执行键盘、分享、音频中断与性能真机验证。
8. 页面级覆盖需要人工确保不与业务冲突。
9. 运行时验收需要 Node.js、可选 npm 依赖和用户手动开启服务端口。

## 如何正确描述完成度

可以：

> 设计系统已生成，静态审查 0 问题，并在微信开发者工具模拟器完成 24 项交互检查与 9 张截图；尚未执行 iOS/Android 真机。

不可以：

> 小程序已在所有设备验证通过。

除非确实记录了开发者工具/真机执行结果。

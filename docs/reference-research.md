## 参考架构中值得采用的思想

1. **Skill 入口 + 本地资源**：SKILL.md 指导工作流，数据/脚本在本地。
2. **结构化设计知识**：产品、风格、配色、规则按 CSV 组织。
3. **可解释检索**：BM25 + 字段权重 + 匹配依据，而不是简单包含。
4. **设计系统生成**：将多领域检索组合为样式/配色/排版/布局/规则。
5. **Master + Overrides**：全局设计系统与页面级例外。
6. **验证与文档**：数据校验、CLI、工作流、测试。
7. **持续持久化**：设计系统可跨会话读取。

这些是通用架构思想，参考项目采用 MIT 许可；本项目仍在数据、字段、算法实现和文案上重新设计。

## 针对小程序重新设计

| 参考方向 | 本项目处理 |
| --- | --- |
| Web/多框架为主 | 以微信小程序为核心，原生/uni-app/Taro 分离 |

## 未直接复制的内容

- 不复制 `products.csv`、`styles.csv`、`colors.csv`、`ux-guidelines.csv`、`typography.csv`、stack CSV 或任何完整数据集；
- 不复制整份 SKILL.md；
- 不复制大量规则后改名；
- 不使用其品牌、图片、文案、示例；
- 不把其 Web 设计规则当小程序规则；
- 不保留本项目不需要的 SaaS/落地页/图表/GSAP 结构。

## 本项目差异化

1. 原创中文小程序设计知识库，包含产品推理、微信平台规则与反模式。
2. 技术栈独立数据与审查：原生、uni-app、Taro。
3. 本地中文检索：bigram + 同义词 + BM25 + 字段权重。
4. 设计系统生成使用产品首选与推理，不是按关键词抓一条色板。
5. 反模板化：每个产品有独立页面结构/设计理由，不默认 SaaS 首页。
6. Master + 页面覆盖 + token 文件（WXSS/SCSS）。
7. 静态审查区分自动/规则辅助/需人工，显式列出未执行环境。
8. 所有平台规则有来源 URL、核验状态与日期。
9. 零第三方 Python 依赖，不要求 AI API Key。
10. 安装器执行本地检索冒烟测试。

## 研究限制

- WebFetch 对 `developers.weixin.qq.com` 的自动安全校验不可用，因此改用 `curl` 获取官方 HTML，并用本地解析器提取文本；未将完整官方文档复制进项目。
- 参考项目的研究只覆盖架构层，不逐条审阅其全部数据；本项目不复用其数据。
- 小程序平台规则会变化，已核对项见 [官方核验](official-verification.md)；未确认项保留“需验证”状态。
- 没有研究参考项目的商业服务或网站；仅研究公开代码/README/许可证。

## 由此形成的决策

- **采用**：本地 CSV、可解释搜索、SKILL 工作流、Master/Overrides、验证命令。
- **重新设计**：所有数据、中文规则、小程序平台约束、技术栈、审查、token 和页面覆盖。
- **已追加实现**：可选的微信开发者工具模拟器验收（CLI + automator；仅模拟器，不包含真机）。
- **暂不实现**：SaaS、可视化画廊、外部 AI 服务、真机自动化、视觉模型自动评分。
- **不复制**：受版权保护的数据集/文案/图片/完整 SKILL。

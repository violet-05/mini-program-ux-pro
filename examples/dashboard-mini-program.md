# 数据看板小程序设计示例

> 示例性质：展示移动端数据看板如何从“桌面表格缩小”转向“决策优先”。

## 需求

- 产品：数据看板小程序
- 技术栈：微信原生
- 核心任务：查看核心指标、筛选维度、定位异常、查看趋势和明细
- 用户：运营、销售、管理者、现场监控人员
- 风格：未指定

```bash
python scripts/generate_design_system.py \

  --stack wechat-native \
  --output ./design-system \
  --format both
```

## 移动端看板原则

1. 首屏 3–5 个核心指标，不是 20 个。
2. 明确时间范围与更新时间。
3. 每个数字有单位、同比/环比或上下文。
4. 图表有图例、坐标/单位、空数据说明。
5. 异常比完整表格更重要。
6. 明细放下一层。
7. 刷新不全屏闪烁，不改变布局。

## 首页

- 范围/更新时间；
- KPI；
- 趋势；
- 异常/告警；
- 明细入口。

## 数据和图表

- 卡片/容器稳定宽度；
- 数字等宽；
- 图表触摸提示；
- 颜色 + 符号/文字；
- 无数据不是错误；
- 部分失败可单独重试。

## 视觉

- 中性浅底 + 蓝色交互；
- 信息密度高但分组清楚；
- 圆角 6–8rpx，阴影极少；
- 一个页面只有一个主筛选；
- 不使用大面积渐变/装饰插画。

## 状态

- 首屏骨架；
- 刷新；
- 部分失败；
- 无权限；
- 空数据；
- 实时更新提示；
- 数据过期提示。

## 应避免

- 所有指标一样大；
- 环形图滥用；
- 没有单位/时间；
- 颜色唯一编码；
- 桌面表格直接缩小；
- 装饰图占据首屏；
- 图表没有空/错状态。

## 技术栈注意

- 高频 setData 要控制；
- 图表若用 canvas，注意原生组件层级；
- 筛选面板避免覆盖原生图表；
- 固定筛选/更新时间不遮数据；
- 数据刷新在 onShow 与定时器之间去重；
- 真机性能优先。

## 验证边界

- 未接入真实数据；
- 未实现图表；
- 未运行开发者工具；
- 未真机验证低端机滚动、图表和刷新；
- 未进行弱网/空/错状态实测。

数据看板的视觉价值来自可比较和可行动；没有真实数据与单位时，不应宣称“完成看板”。

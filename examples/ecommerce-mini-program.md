# 电商小程序设计示例

> 示例性质：演示如何从知识库生成设计系统，不代表已完成页面或真机验收。

## 需求

- 产品：综合电商小程序
- 技术栈：微信原生
- 核心任务：搜索/分类找商品、比较价格规格、加购/购买、查看订单
- 用户：价格敏感与探索性购物并存
- 风格：没有指定，由产品类型和推理规则推导

## 生成命令

```bash
python scripts/generate_design_system.py \
  --product "综合电商小程序" \
  --stack wechat-native \
  --output ./design-system \
  --format both
```

## 结果（当前知识库）

| 项 | 结果 |
| --- | --- |
| 产品记录 | `prod-ecommerce` 综合电商 |
| 风格 | `style-premium-commerce` 高级商业质感 |
| 配色 | `palette-commerce-warm` 暖调商业（浅色） |
| 排版 | `type-commerce-numeric` 商业价格数字 |
| 页面 | 首页、分类、商品列表、商品详情、购物车、结算、订单、个人中心 |
| 推理 | `reason-commerce`、`reason-local-life` |

## 为什么不是通用 SaaS 首页

电商首屏的核心不是品牌故事，而是：

1. 我在找什么（搜索/分类）；
2. 什么值得买（价格、活动、信任）；
3. 如何快速比较（卡片信息顺序）；
4. 如何安全购买（规格、配送、支付、售后）。

所以首页结构是“搜索/身份 → 活动或精选 → 分类/主题 → 推荐 → 服务保障”，而不是“大标题 + 四宫格 + 三卡片”。

## 视觉方向

- 暖调纸白背景，品牌红棕承担主操作；
- 价格使用稳定数字宽度和更高字重；
- 商品图片比例统一；
- 卡片少阴影，主要靠图片/价格/间距分层；
- 主按钮每屏唯一，底部购买栏安全区；
- 活动色只在活动区出现，不渗透全站。

## 关键页面

### 首页

- 顶部搜索 + 位置/身份；
- 一个主活动或精选，不堆多个同权轮播；
- 分类有真实用途；
- 推荐商品卡信息一致；
- 服务承诺（配送/售后）靠近购买决策，而不是藏在帮助中心。

### 商品详情

- 图片/标题/价格/规格首屏可见；
- 服务与配送信息明确；
- 详情长图不替代规则；
- 底栏包含价格/优惠摘要和唯一主操作；
- 规格未选不可提交。

### 购物车/结算

- 失效商品分区；
- 总价与结算按钮关系清楚；
- 删除可撤销/确认；
- 提交防重复；
- 支付结果提供凭证与订单查询。

## 应避免

- `anti-card-everywhere`
- `anti-product-hierarchy`
- `anti-meaningless-gradient`
- `anti-primary-action-weak`
- `anti-bottom-bar-overlap`
- `anti-safe-area-error`

## 验证边界

- 设计系统为静态生成；
- 未编译页面；
- 未在微信开发者工具运行；
- 未真机验证图片、键盘、支付和底栏。

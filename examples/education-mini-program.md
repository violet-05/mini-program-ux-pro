# 教育小程序设计示例

> 示例性质：展示学习路径、课程与 Taro 技术栈的设计系统生成。

## 需求

- 产品：教育学习小程序
- 技术栈：Taro
- 核心任务：每日学习、刷题/听课、查看计划、复习错题、查看进度
- 用户：学生、备考人群、家长
- 风格：未指定

## 生成命令

```bash
python scripts/generate_design_system.py \
  --product "教育学习小程序" \
  --stack taro \
  --output ./design-system \
  --format both
```

## 结果（当前知识库）

| 项 | 结果 |
| --- | --- |
| 产品记录 | `prod-education` 教育学习 |
| 风格 | `style-editorial` 编辑式设计 |
| 配色 | `palette-education-focus` 学习专注 |
| 排版 | `type-editorial-serif` 编辑式宋体标题 |
| 页面 | 首页、课程列表、课程详情、表单、学习看板、个人中心 |
| 推理 | `reason-learning`、`reason-gamified` |
| 冲突 | 产品信息密度为“中高”，编辑式风格建议低密度，需在实现时平衡 |

## 为什么选编辑式

教育产品不只是题库列表。需要：

- 学习目标/路径；
- 课程与讲义的叙事；
- 进度与下一步；
- 内容可读性；
- 成就反馈但不干扰学习。

编辑式排版帮助建立章节和内容层级；学习看板/题库仍使用稳定的数据和操作组件。

## 视觉方向

- 纸张感浅底 + 深墨正文；
- 蓝色品牌用于链接/主操作，金色用于提醒；
- 标题宋体、正文系统无衬线；
- 进度条、步骤、课程卡、任务；
- 游戏化只用于鼓励，不做持续干扰；
- 教育内容优先，广告/推荐靠后。

## 关键页面

### 首页

- 今日学习/继续学习；
- 学习计划/进度；
- 课程或题库入口；
- 错题/待复习；
- 成就（克制）。

### 课程详情

- 标题/讲师/适合人群；
- 试听与目录；
- 进度；
- 价格/报名（如付费）；
- 评价与退款规则；
- 固定 CTA。

### 学习看板

- 学习时长/连续天数/正确率；
- 趋势；
- 待复习；
- 不只靠颜色；
- 手机首屏只保留 3–5 指标。

## 冲突处理

编辑式低密度 vs 教育中高信息密度：

- 首页/内容页使用编辑式节奏；
- 题库/数据区改用紧凑列表；
- 同一项目不混用两套字体/颜色，只调整密度和容器；
- 在页面覆盖中记录例外。

## Taro 注意

- `pages` 在 app.config 注册；
- 使用 `@tarojs/components` 的 View/Text/Image；
- 不把 React Router/DOM 当 Taro 小程序路由；
- 检查 px→rpx 配置；
- `useDidShow` 等生命周期处理刷新；
- 微信目标真机验证分享/键盘/安全区。

## 应避免

- 游戏化奖励压过学习；
- 课程卡只有封面；
- 进度只靠颜色；
- 详情页只有营销文案；
- 广告打断学习；
- 只在 H5 调试就认为 Taro 微信端完成。

## 验证边界

- 未编译 Taro 微信目标；
- 未实现课程/题库数据；
- 未验证支付、登录、学习进度；

本示例是设计系统示例，不是教育产品功能实现。

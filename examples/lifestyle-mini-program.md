# 生活服务小程序设计示例

> 示例性质：展示“位置 + 服务范围 + 预约”的任务结构。

## 需求

- 产品：生活服务小程序
- 技术栈：微信原生
- 核心任务：找家政/维修、比较报价、预约上门、查看订单
- 用户：社区居民、家庭用户
- 风格：未指定

## 生成命令

```bash
python scripts/generate_design_system.py \
  --product "生活服务小程序" \
  --stack wechat-native \
  --output ./design-system \
  --format both
```

## 设计重点

生活服务不是电商商品列表的复制。用户首先要确认：

- 商家/服务者是否服务我的位置；
- 服务包含什么、不包含什么；
- 上门费/材料费/起步价；
- 可选时间；
- 取消和售后规则；
- 评分是否真实。

## 首页

- 位置/服务范围；
- 服务分类（保洁、维修、家政等）；
- 附近服务者/套餐；
- 保障与售后；
- 订单入口。

不使用巨大的品牌 banner 挤压“找服务”。

## 服务详情

- 服务名称、价格范围、计价方式；
- 服务范围/不包含项；
- 评分与真实评价；
- 可预约时间；
- 服务者信息/资质（如真实）；
- 固定预约/联系按钮；
- 取消规则。

## 预约

- 日期/时段可用性；
- 地址录入；
- 费用摘要；
- 上门说明；
- 确认防重复；
- 成功凭证。

## 视觉与语气

- 柔和但不低对比；
- 暖白背景、鼠尾草绿/陶土色；
- 大触控区；
- 卡片轻，信息分组清楚；
- 评分不只靠星星；
- 价格透明，不用“9.9起”掩盖费用。

## 应避免

- 服务范围/费用藏起来；
- 预约无可用时段；
- 评分虚高；
- 售后入口难找；
- 所有页面用同一张卡片模板；
- 固定预约栏遮挡服务说明。

## 技术栈注意

原生小程序：

- 预约表单处理键盘；
- 固定底栏安全区；
- 地址/位置权限按需；
- 电话/客服能力按平台验证；
- 订单状态以服务端为准。

## 验证边界

- 未实现实际预约；
- 未接位置/支付/客服；
- 未真机验证键盘、安全区和地址表单；
- 未验证服务者资质与评价数据。

本示例只展示任务与设计方向，不证明业务可用。

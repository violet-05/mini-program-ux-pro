# 组件设计

## 原生优先

微信提供了导航、TabBar、按钮、输入、picker、switch、radio、checkbox、scroll-view、image 等基础组件。优先使用或模仿平台控件，原因：

- 平台已处理触控、键盘、安全区和部分可访问性；
- 系统升级更稳；
- 用户熟悉；
- 维护成本低。

只有品牌/业务确有需求时自定义，且需要补齐所有状态。

## 组件的完整状态

一个可交互组件至少定义：

- 默认；
- 按压/聚焦；
- 禁用；
- 加载/处理中；
- 成功；
- 失败；
- 选中/未选中（适用）；
- 空/无数据（适用）；
- 小屏/大字号/深色模式。

按钮只有默认样式，是静态稿，不是组件。

## 组件 API

原生自定义组件通过 properties 接收数据，通过 triggerEvent 发事件：

```js
Component({
  properties: {
    label: { type: String, value: '' },
    disabled: { type: Boolean, value: false }
  },
  methods: {
    onTap() {
      if (!this.data.disabled) {
        this.triggerEvent('action')
      }
    }
  }
})
```

不要把父页面内部实现暴露给组件，也不要依赖跨组件后代选择器。理解 `styleIsolation` 后再开放外部样式。

## 组件清单

| 组件 | 核心要求 |
| --- | --- |
| 原生导航 | 标题、返回、胶囊、安全区 |
| 自定义导航 | 运行时计算、返回、对比度 |
| TabBar | 2–5 项，文字，本地图标，选中态 |
| 搜索框 | 确认键、清空热区、键盘、建议 |
| 分类导航 | 长文本、横向滚动、选中态 |
| 商品卡 | 图片比例、标题行数、价格、标签、独立按钮 |
| 筛选面板 | 已选条件、重置、结果数、安全区 |
| 弹窗 | 单一模态、关闭、危险操作、键盘 |
| Action Sheet | 危险项、滚动、取消、安全区 |
| Toast | 短文案、非关键错误、不堆叠 |
| 表单 | 标签、错误、提交锁、保留输入 |
| 输入框 | 类型、焦点、错误、键盘 |
| 开关 | 即时生效、失败回滚、可读名称 |
| 日期/Picker | 当前值、范围、取消 |
| 空状态 | 原因、下一步、不是错误 |
| 加载 | 范围、超时、取消 |
| 骨架 | 与真实布局一致 |
| 错误 | 影响、重试、客服 |
| 加载更多 | 加载中、无更多、失败重试 |
| 图片预览 | 比例、失败、索引 |
| 底部操作栏 | 唯一主操作、安全区、键盘 |
| 订单状态 | 文字+图标+颜色 |
| 图表 | 单位、图例、时间范围、空数据 |
| 步骤条 | 总步数/当前/错误，可返回 |
| 分享 | 平台真实分享，不伪造 |

完整规则见 [components.csv](../data/components.csv)。

## 视觉一致性

- 组件高度、圆角、边框来自 token；
- 同一语义的颜色一致；
- 图标来自同一图标库；
- 状态样式统一；
- 不在页面内重复定义按钮/卡片；
- 深浅色模式有对应 token。

## 布局与内容适应

组件必须承受：

- 长标题；
- 长用户名；
- 长价格/数值；
- 无图片/图片失败；
- 系统大字号；
- 320px 窄屏；
- 大屏；
- 空数据；
- 网络错误。

不能只在理想数据下截图。

## 可访问性

- 按钮有可读名称；
- 图标按钮不只有图标；
- 输入有标签；
- 状态不只靠颜色；
- 弹窗可关闭；
- 表单错误可读；
- 触摸目标足够；
- 自定义控件保留语义。

## 反模式

- 每个页面自定义一套按钮；
- 组件只做默认态；
- 用 view 拼输入框但没有键盘/焦点处理；
- 把固定底栏写进每个页面分别计算；
- 图表没有单位；
- Toast 代替字段错误；
- 图片卡没有失败态；
- 弹窗堆叠。

## 验证

- 组件在 3 个以上页面复用；
- 长文本/空/错/加载/深色/大字号；
- iOS/Android 真机；
- 键盘与安全区；
- 交互状态；
- 样式隔离。

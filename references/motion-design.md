# 动效设计

## 动效的目的

动效应至少服务一个目的：

- 表示状态变化（加载、成功、错误）；
- 表示空间关系（页面/弹层进入）；
- 引导注意（新消息、异常）；
- 维持连续性（播放/拖拽/滚动）；
- 提供品牌语气（少量、可关闭）。

如果移除后不影响理解和操作，它可能只是装饰。

## 时长

推荐范围：

| 类型 | 时长 |
| --- | ---: |
| 按压反馈 | 80–120ms |
| 状态切换 | 120–180ms |
| 弹层/抽屉进入 | 180–260ms |
| 页面转场 | 180–300ms |
| 复杂品牌时刻 | 最长约 400ms，且可跳过 |

超过 400ms 的频繁交互动效通常会造成等待感。加载/进度动画可更长，但必须有信息。

## 缓动

常用标准缓动：

```css
cubic-bezier(0.2, 0.8, 0.2, 1)
```

- 进入：较快开始，柔和结束；
- 退出：通常比进入更快；
- 避免全站使用同一条弹跳曲线。

## WXSS 实现

优先使用 `transform` 和 `opacity`：

```css
.card-enter {
  opacity: 0;
  transform: translateY(12rpx);
  animation: card-in 180ms cubic-bezier(0.2, 0.8, 0.2, 1) forwards;
}

@keyframes card-in {
  to {
    opacity: 1;
    transform: translateY(0);
  }
}
```

避免：

- 动画 `width/height/top/left` 触发重排；
- 滚动时实时改变模糊半径；
- 每个列表项都绑定独立复杂动画；
- 无限循环装饰动画。

## 页面转场

小程序页面转场由平台控制，通常不应自绘整套转场。自定义导航/全屏媒体页要：

- 保持返回可预期；
- 不遮挡胶囊；
- 控制背景透明度和文字对比；
- 真机验证性能。

## 加载动效

- 首屏骨架与真实布局一致；
- 骨架低对比、不快闪；
- 局部 loading 只覆盖局部；
- 按钮 loading 锁定操作；
- 长任务显示进度/可取消；
- 失败后停止并转错误态。

## 成功/错误反馈

- 重要结果用页面内状态，不仅 toast；
- 成功可短暂动画，但必须同时有文字；
- 错误不使用庆祝动效；
- 支付成功要有凭证，不依赖彩带动画。

## 减弱动效

平台是否支持 `prefers-reduced-motion` 需按 WebView/Skyline 验证。无论支持与否：

- 不提供影响任务的无限动画；
- 允许关闭品牌装饰动效；
- 动效失败不影响内容；
- 动画不是唯一状态提示。

## 性能

- 低端 Android 实测；
- 避免大面积模糊/阴影动画；
- 控制同时动画数量；
- 使用 CSS 动画或平台能力，避免高频 setData；
- 页面不可见时停止动画/计时器。

## 反模式

- 所有模块入场飞入；
- 每屏都有粒子/流光；
- 弹窗从四个方向乱入；
- 按钮无限呼吸；
- 滚动视差干扰阅读；
- 动效遮住操作；
- 不能关闭；
- 用动效掩盖加载/错误缺失。

## 检查

- [ ] 动效有目的；
- [ ] 时长与距离匹配；
- [ ] 不影响任务；
- [ ] 低端机不卡顿；
- [ ] 支持关闭/降级；
- [ ] 状态有文字说明；
- [ ] 真机验证。

# 响应式与设备适配

## 设计基准

小程序常用 750rpx 设计宽；官方设计指南给出 375px 与 390px 基准。实际设备宽高比和可用高度不同，不能把设计稿像素当真实像素。

策略：

- 横向尺寸用 rpx/百分比；
- 文字用 rpx 但不随屏幕无限缩小；
- 关键容器设置最大宽度；
- 底部/顶部固定元素结合安全区；
- 用真实设备而非只靠模拟器。

## 小屏

320–360px 宽：

- 双列卡片可能过窄；
- 长标签/价格容易换行；
- 固定底部栏占空间；
- 首屏主任务可能被压缩。

处理：

- 重要信息单列；
- 标题行数/字号 token；
- 允许卡片高度变化；
- 把次要入口收起；
- 测试 320px。

## 主流屏

375×667、390×844：

- 核心路径必须完整；
- 固定底栏和安全区；
- 图片/卡片比例；
- 长标题；
- 系统字号。

## 大屏/平板/PC

微信小程序可在大屏/PC 运行（按平台支持范围）。设计：

- 内容最大宽度，如 960–1120rpx；
- 居中；
- 不要无限拉伸卡片；
- 分栏只在真正提高效率时使用；
- 触控/鼠标交互都要验证；
- 底部 TabBar 可能不适合超宽屏，需按平台能力与产品决定。

## 横屏

如产品支持：

- 重新布局，不简单旋转；
- 安全区变化；
- 键盘；
- 视频/地图等原生组件；
- 真机验证。

不支持横屏时明确锁定，不假设平台行为。

## 长文本

- 中文/英文/数字/Emoji 混合；
- 无空格长串；
- 地址、URL、用户昵称；
- 系统大字号；
- 标题 2–3 行；
- 价格不换行；
- 图片说明。

## 高度适配

宽高比不是固定：

- 首屏可能更矮；
- 键盘减少可视区；
- 刘海/手势条改变顶部/底部；
- 弹窗最大高度需可滚动。

不要用 `100vh` 假设固定可用高度；小程序也不总有完整浏览器 vh 语义。

## 图片与媒体

- 固定比例容器；
- mode 正确；
- 多图裁切一致；
- 图片失败占位；
- 大图压缩；
- 视频比例/控件；
- 原生媒体组件层级。

## 测试矩阵

| 宽度 | 设备 | 检查 |
| ---: | --- | --- |
| 320 | 小屏/模拟 | 横向溢出、双列 |
| 375 | iPhone SE/主流 | 首屏、底栏 |
| 390 | iPhone 主流 | 刘海/手势区 |
| 414/430 | 大屏手机 | 留白、卡片拉伸 |
| 768+ | 平板/PC | 最大宽度、分栏 |
| 键盘 | iOS/Android | 输入/按钮 |

## 检查

- [ ] 320px 无横向滚动；
- [ ] 主流尺寸首屏任务完整；
- [ ] 长文本不撑破；
- [ ] 图片比例一致；
- [ ] 固定栏安全区正确；
- [ ] 大屏有最大宽度；
- [ ] 系统字号放大；
- [ ] 真机验证。

# 安全区域

## 为什么需要安全区

手机屏幕存在：

- 顶部状态栏；
- 刘海/挖孔；
- 右上角胶囊；
- 底部手势条/圆角；
- 键盘弹起后的可视区域变化。

固定元素如果贴住屏幕边缘，可能被系统 UI 覆盖或难以点击。微信官方设计指南要求考虑不同机型和点击区域；具体 CSS/API 行为按基础库和渲染引擎验证。

## 底部安全区

固定底栏常用：

```css
.bottom-bar {
  position: fixed;
  left: 0;
  right: 0;
  bottom: 0;
  padding-bottom: calc(16rpx + env(safe-area-inset-bottom));
}
```

同时内容区要占位：

```css
.page {
  padding-bottom: calc(100rpx + env(safe-area-inset-bottom) + 32rpx);
}
```

如果目标环境不支持 `env()`，需要：

- 使用运行时窗口安全区信息；
- 提供保守的基础 padding；
- 在真机检查；
- 不假设所有机型一致。

`env(safe-area-inset-bottom)` 在开发者工具可能为 0 或与真机不同，不能只看模拟器。

## 顶部

自定义导航需要：

- 状态栏高度；
- 胶囊 top/bottom/left/right；
- 导航内容高度；
- 左右安全边距；
- 滚动后背景变化。

不要把导航高度写死成 44px 或 88rpx。不要覆盖胶囊或把按钮放在胶囊区域。

## TabBar

原生 TabBar 由平台处理，但它上方的内容仍需考虑底部占位。自定义 TabBar 必须：

- 加安全区；
- 固定时给页面内容占位；
- 处理页面切换和选中态；
- 键盘场景隐藏/让位（如适用）。

## 弹窗/Action Sheet

- 底部弹层加安全区；
- 内部滚动不能把按钮滚出可点区域；
- 关闭按钮固定且易点；
- 避免被原生组件覆盖。

## 键盘

安全区不等于键盘。键盘弹起会改变可视区域。必须分别处理：

- 输入框 adjust-position/滚动；
- 底部操作栏让位；
- 提交按钮可见；
- 键盘收起后恢复布局。

真机检查 iOS/Android，第三方输入法也要测。

## 大屏/PC

- 限制内容最大宽度；
- 底栏不要横跨超宽屏导致内容分散；
- 居中内容 + 明确边界；
- 顶部/底部安全区与 PC 客户端能力按平台文档。

## 验证矩阵

| 场景 | 检查 |
| --- | --- |
| 全面屏 iPhone | 底部手势条、顶部刘海、胶囊 |
| 非全面屏 iPhone | 状态栏、底栏间距 |
| Android 手势导航 | 底部手势区 |
| Android 三键导航 | 底栏与导航栏 |
| 小屏 | 固定内容是否挤压 |
| 大屏/平板/PC | 最大宽度、布局 |
| 键盘弹起 | 输入区、提交按钮 |
| 页面滚动到底 | 最后内容是否被遮挡 |

## 常见错误

- 底栏 `bottom: 0` 无 padding；
- 内容没有底部占位；
- 只在开发者工具看；
- 所有设备用同一个 padding；
- 自定义导航硬编码状态栏；
- 弹窗底部按钮被手势条覆盖；
- 键盘与安全区混为一谈。

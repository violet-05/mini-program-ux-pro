# 交互审查工作流

## 目标

验证页面不仅能看，还能完成真实任务：能返回、能输入、能提交、能恢复、不被键盘或安全区遮挡。

## 1. 环境声明

必须区分：

- 静态代码审查；
- 微信开发者工具模拟交互；
- 浏览器原型；
- iOS/Android 真机；
- 弱网/断网。

报告每一项在哪个环境执行。未执行不能算通过。

## 2. 可选自动化

如果用户已安装 DevTools 并开启服务端口，可运行仓库自带的模拟器验收：

```bash
python scripts/devtools_adapter.py --cli "<cli.bat>" run --project verification --port 9420
```

它只覆盖开发者工具模拟器，不覆盖真机键盘、分享、音频中断和性能。结果与截图在 `verification/artifacts/`。

## 3. 核心路径

至少覆盖：

1. 首页/启动；
2. 进入核心任务页；
3. 搜索/筛选/选择；
4. 表单/规格/授权；
5. 提交/支付；
6. 结果页；
7. 返回与再次进入；
8. 分享/扫码进入（如适用）。

## 4. 逐项检查

### 导航

- 系统返回、页面内返回、手势返回一致。
- 从分享/扫码进入时不会回到错误层级。
- TabBar 切换不叠加页面栈。
- 筛选、滚动和输入状态保留。

### 操作反馈

- 按下态、loading、成功、失败、禁用。
- 无死按钮。
- 提交锁定防重复。
- 危险操作有确认/撤销。
- 取消与关闭真实生效。

### 表单

- 键盘类型正确。
- 标签可见，错误就近。
- 提交失败保留输入。
- 多错误摘要可定位。
- 键盘不遮挡字段和提交按钮。

### 加载/空/错误

- 加载有范围、超时、重试。
- 空状态有原因和下一步。
- 错误说明影响和恢复方式。
- 断网/弱网不丢数据或重复扣款。
- 支付结果以服务端订单为准。

### 手势与滚动

- 页面和内部滚动不互相抢。
- 弹窗打开时背景不滚动。
- 点击不与滑动手势冲突。
- 固定底栏不遮挡最后内容。

### 平台能力

- 分享真实可触发，取消/失败有结果。
- 权限在任务前请求，拒绝有替代。
- 隐私协议和撤回入口可用。
- 原生组件（地图/视频/canvas）层级正确。
- 自定义导航/胶囊/状态栏正常。

## 5. 弱网与异常

- 首屏慢：骨架/局部 loading。
- 请求超时：可重试，不无限转圈。
- 断网：保留输入或显示恢复路径。
- 重复点击：幂等，无重复订单。
- 上传中断：可取消/重试。
- 支付未知：可查单，不重复扣款。
- 权限拒绝：仍可浏览和使用替代路径。

## 7. 发现问题后的处理

- 如果用户只要求审查：输出问题与建议，不修改代码。
- 如果用户要求修复：制定最小修改计划，优先 P0/P1。
- 修改后必须重新走同一路径并检查回归。
- 静态工具只能发现部分线索，不能替代运行时验证。

## 8. 输出

- 每项是否执行、在哪个环境；
- 问题证据（截图/路径/错误）；
- 严重度与修复建议；
- 未验证项；
- 是否存在新问题。
